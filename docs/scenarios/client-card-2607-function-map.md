### 2.2. Что проверяет карточка ФЛ

- **Карточка физ. лица → Двухколоночное отображение** — основной блок проверки
  (21 пункт). Покрывает шапку (ФИО, папки/теги, заметка), блок данных
  (примечание, ответственный, дополнительные адреса, поведение при изменении
  ширины, скролл), блок параметров (скролл, «чипсы»), карточку в отдельной
  вкладке и переключение одно-/двухколоночного режима.
- **Вкладки карточки** — «Параметры» (4), «Вложения» (2), «Активности» (1),
  «Покупки» (1), «Чаты» (1), «Бонусы» (1), «Рекомендации» (1). В основном
  проверяется вёрстка блока и отдельные поведения вкладок.
- **Общие проверки карточки** — открытие, интерфейс, контролы тулбара,
  кнопка «Свернуть/Развернуть», статичность вкладки «Контакты», скролл
  контактных данных, сохранение фокуса.
- **Доп. поля** — работа с дополнительными полями.
- **Мини-карточка** — регресс и сохранение режима при открытии полной карточки.
- **Демо-режим** — регресс карточки в демо-режиме.
- **Изменения в API** — проверка изменений API, связанных с карточкой ФЛ.
- **Конвертация старых ФЛ** — не проверяется (вне скоупа).

## 6. Проблемные точки и пробелы

### 6.1. Явный дефект

- **Карточка ФЛ → Карточка физ. лица → Двухколоночное отображение → ТК: Пустая карточка ФЛ в двухколоночном виде** — «Выпускаем с ошибками» (docId 603532336).

Из-за этого родительские этапы «Карточка физ. лица» и «Двухколоночное
отображение», а также корень «Функциональное тестирование», агрегируются
в статус «Выпускаем с ошибками». Нужно уточнить, какой именно дефект
зафиксирован в пункте и есть ли связанная задача.

### 6.2. Не тестировалось

- **Нефункциональное тестирование + АТ → Автотесты**.
- **Нефункциональное тестирование + АТ → Тестирование безопасности**.
- **Нефункциональное тестирование + АТ → Тестирование клиентской производительности**.
- **Нефункциональное тестирование + АТ → Нагрузочное тестирование**.

Это нефункциональные направления. Для них нет ни плана, ни статуса
«В процессе». Если они входят в релизный скоуп, нужен отдельный план.

### 6.4. Чего нет в проверке

- Негативных сценариев по данным: неверные значения, обязательность полей,
  границы длины/чисел — в явном виде не выделены.
- Проверок прав на уровне карточки ФЛ: «Права» есть только в базовом блоке,
  а в мобильном — «Не проверяем».
- Контрактных и негативных проверок API: есть только «Изменения в API».
- Кросс-браузерности и адаптивности за пределами изменения ширины блоков.
- Восстановления после ошибок сети/5xx для веб-карточки.
- Описаний шагов и ожидаемых результатов в пунктах — это главный барьер
  для передачи проверки другому QA и для автоматизации.
