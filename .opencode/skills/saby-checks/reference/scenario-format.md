# Формат сценария для `saby_check_import_scenario`

## Схема

```ts
type Scenario = {
  sections: Section[];
};

type Section = {
  name: string;                 // название этапа
  description?: string;         // требования/контекст этапа
  plannedMinutes?: number;      // план этапа, 0..6000
  points: Point[];
};

type Point = {
  type?: 'ТК' | 'ЧЛ' | 'Т';     // по умолчанию ТК
  name: string;                 // обязательно с префиксом ТК/ЧЛ/Т
  comment: string;              // «Общее описание» → «Комментарий»
  precondition?: string | string[]; // «ПРЕДУСЛОВИЕ: 1. ...»
  steps?: string | string[];    // «ШАГИ: 1. ...»
  expected?: string;            // «ОЖИДАЕМЫЙ РЕЗУЛЬТАТ: ...»
  description?: string;         // готовое описание, если уже собрано
  statusComment?: string;       // только комментарий статуса, обычно пустой
  plannedMinutes?: number;      // не более 5
  status?: string | number;     // по умолчанию «Не тестировался»
  assigneeId?: number;          // id сотрудника
  mark?: 'pc' | 'mobile_important' | 'mobile_minor'
       | 'mobile_noncritical' | 'automated';
};
```

Ограничения:

- `sections` — от 1 до 200 пунктов суммарно (настраивается `maxPoints`);
- названия этапов и пунктов уникальны в пределах родителя;
- у теста обязателен `comment`, не совпадающий с `name`;
- `plannedMinutes` — не более 5;
- `parentSectionId` — `structureId` существующего корневого этапа.

## Как формулировать тесты

Плохо:

> Проверить карточку клиента.

Хорошо:

> **ТК: Сохранение телефона**  
> Комментарий: проверяем сохранение телефона после перезагрузки карточки.  
> ПРЕДУСЛОВИЕ:
> 1. Открыть карточку клиента.
> 2. Подготовить клиента с правами на редактирование.
>
> ШАГИ:
> 1. Изменить телефон на +1 555 010 20 30.
> 2. Нажать «Сохранить».
> 3. Перезагрузить карточку.
>
> ОЖИДАЕМЫЙ РЕЗУЛЬТАТ:
> Телефон сохранён и отображается в формате +1 555 010 20 30.

Правила:

1. Название начинается с `ТК`, `ЧЛ` или `Т`.
2. Комментарий — короткое «что проверяем», не повторяет название.
3. Предварительные шаги — в «Описание», формат `ПРЕДУСЛОВИЕ:`.
4. В предусловии — подготовка: роль, данные, инструмент, открытие карточки.
5. Плановое время — не более 5 минут.
6. Пометки: `pc` — ПК, `mobile_important` — важный МК,
   `mobile_minor` — незначительный МК, `mobile_noncritical` — МК
   не критичный функционал, `automated` — АТ.
7. Описание не должно совпадать с названием.
8. Один тест — одна проверяемая цель.

## Что вернёт импорт

```json
{
  "dryRun": false,
  "check": { "id": 599752330, "name": "Проверка № 2607", "url": "..." },
  "totalSections": 1,
  "totalPoints": 2,
  "plan": [
    { "action": "createStage", "name": "Карточка клиента: шапка" },
    {
      "action": "createPoint",
      "section": "Карточка клиента: шапка",
      "name": "ТК: Обязательное поле ФИО",
      "plannedMinutes": 5,
      "mark": "pc"
    }
  ],
  "warnings": [],
  "createdDocIds": [633434480, 633434483],
  "verification": { "ok": true, "missing": [] }
}
```

`createdDocIds` — id документов, созданных именно этим вызовом.
Их можно удалить через `saby_check_item_delete`, если пользователь
разрешил очистку.
