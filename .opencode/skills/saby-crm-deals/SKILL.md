# API сделок Saby CRM

## Когда использовать

- Нужно создать, прочитать, изменить или удалить сделку (`Лид`).
- Нужно перевести сделку на другой этап или откатить её.
- Нужно добавить товары, связать сделку с документом или прочитать состав.
- Нужно подготовить сделку как данные для UI-теста.
- Нужно разобрать, почему вызов метода возвращает ошибку контракта.

Полное исследование стенда: `docs/api/sbis-crm-deals.md`.

## Транспорт

```
POST {SABY_BASE_URL}/service/?x_version=26.5120-78
```

Авторизация — сессионные cookie (`credentials: include`), отдельного токена нет.

Конверт:

```json
{
  "jsonrpc": "2.0",
  "protocol": 7,
  "method": "<Сервис.Метод>",
  "params": { },
  "id": 1
}
```

Заголовки:

| Заголовок | Значение | Зачем |
|---|---|---|
| `content-type` | `application/json; charset=UTF-8` | тело запроса |
| `x-requested-with` | `XMLHttpRequest` | признак AJAX |
| `x-adaptive` | `false` | без него часть документных методов не маршрутизируется |
| `x-calledmethod` | `Lid.ProchitatDlyaUchastnika` | латиница: сервис + метод |
| `x-originalmethodname` | `base64(UTF-8("<Кириллица>.<Метод>"))` | исходное имя метода |
| `x-saby-appid` | из захваченного запроса | идентификатор приложения |
| `x-saby-appversion` | `26.5120` | версия клиента |
| `x-saby-cfgid` | из захваченного запроса | идентификатор конфигурации |

`x-calledmethod` не может содержать кириллицу: `btoa` бросит
`InvalidCharacterError`. Кодируй исходное имя отдельно:

```js
const b64 = (s) => btoa(String.fromCharCode(...new TextEncoder().encode(s)));
const latin = "Lid.ProchitatDlyaUchastnika";
const original = "Лид.ПрочитатьДляУчастника";
```

Рабочий helper:

```js
const call = async (latin, method, params) => {
  const resp = await fetch("/service/?x_version=26.5120-78", {
    method: "POST",
    credentials: "include",
    headers: {
      "content-type": "application/json; charset=UTF-8",
      "x-adaptive": "false",
      "x-requested-with": "XMLHttpRequest",
      "x-calledmethod": latin,
      "x-originalmethodname": b64(method),
      "x-saby-appid": "<из запроса>",
      "x-saby-appversion": "26.5120",
      "x-saby-cfgid": "<из запроса>",
    },
    body: JSON.stringify({ jsonrpc: "2.0", protocol: 7, method, params, id: 1 }),
  });
  return resp.json();
};
```

## Формат record

Saby передаёт записи не объектами, а плоскими структурами:

```json
{
  "_type": "record",
  "f": 0,
  "d": [56224, "комментарий"],
  "s": [
    { "n": "@Документ", "t": "Число целое" },
    { "n": "Примечание", "t": "Строка" }
  ]
}
```

- `s` — схема: имя и тип поля;
- `d` — значения в том же порядке;
- `f` — версия формата;
- `_type` — `record` или `recordset` (у `recordset` в `d` массив строк).

Разбор ответа:

```js
const cols = result.s.map((c) => c.n);
const row = result.d[0];
const obj = Object.fromEntries(cols.map((name, i) => [name, row[i]]));
```

## Модель сделки

Сделка — документ `Лид`.

| Понятие | Поле |
|---|---|
| Идентификатор | `@Документ` |
| Номер | `Номер` / `ЧисловойНомер` |
| UUID | `ИдентификаторДокумента` |
| Тема (регламент) | `Лид.Регламент` |
| Этап | `Лид.Фаза` |
| Переход | `Лид.Переход` |
| Клиент | `Лид.Контрагент` + `КлиентНазвание` |
| Ответственный | `Лид.Сотрудник` |
| Подразделение | `Лид.Подразделение` |
| Комментарий | `Примечание` |
| Признак удаления | `Удален` |

### Как узнать ID темы и этапов

1. Темы ищутся через список сделок с фильтром по теме:

```json
{
  "method": "Lead.LeadsList",
  "params": {
    "Фильтр": { "_type": "record", "f": 0, "d": [26301849],
                "s": [{ "n": "Регламент", "t": "Число целое" }] },
    "Сортировка": null,
    "Навигация": { "_type": "record", "f": 0,
      "d": ["forward", true, 200, null],
      "s": [{ "n": "Direction", "t": "Строка" },
            { "n": "HasMore", "t": "Логическое" },
            { "n": "Limit", "t": "Число целое" },
            { "n": "Position", "t": "Запись" }] },
    "ДопПоля": []
  }
}
```

Ответ содержит `Лид.Регламент`, `КлиентНазвание`, `Фаза`, `@Документ`, `Номер`.

2. Этапы и переходы темы — через карточку:

```json
{
  "method": "CRMEvent.AvailableDocCommands",
  "params": {
    "doc_rec": { "_type": "record", "f": 0, "d": [<ИдСделки>, <ИдТемы>],
      "s": [{ "n": "@Документ", "t": "Число целое" },
            { "n": "Регламент", "t": "Число целое" }] },
    "event": null,
    "ex_params": { "phase_id": <ТекущаяФаза> },
    "preload_events": null
  }
}
```

В ответе для каждого перехода важны:

- `PassId` — идентификатор перехода (не `Идентификатор`!);
- `Название` — подпись;
- `СледующиеЭтапы.PhaseId` — целевой этап;
- `ТребуетсяКомментарий`, `ТребуетсяУказатьИсполнителя`.

## CRUD

### Создание — `Лид.Создать` ⚠️

Прямой вызов в текущей версии требует обёртку с `Расширение` и `Фильтр`:

```
В объекте нет поля Расширение
В объекте нет поля Фильтр
```

Точный контракт не подтверждён. Надёжный путь:

1. Создать сделку через UI (кнопка «Создать» на `page/crm-deals`).
2. Захватить запрос `Лид.Создать` в network и переиспользовать его тело.
3. Либо создать карточку и дальше работать через `Лид.Записать`.

Не выдумывай поля `Расширение`/`Фильтр` — снимай их с реального запроса.

### Чтение — `Лид.ПрочитатьДляУчастника` ✅

```json
{
  "method": "Лид.ПрочитатьДляУчастника",
  "params": {
    "ИдО": 56224,
    "ИмяМетода": "Лид.ListCard",
    "ДопПоля": { "ИмяОбъекта": "Лид" }
  }
}
```

Ответ — `recordset` с 298 колонками и одной строкой. Ключевые поля:
`@Документ`, `Номер`, `ИдентификаторДокумента`, `Лид.Фаза`,
`Лид.Фаза.Название`, `Лид.Регламент`, `Лид.Контрагент`, `Лид.Сотрудник`,
`Лид.Подразделение`, `Примечание`, `Удален`, `Статус`.

Быстрые данные шапки:

```json
{ "method": "Lead.GetCardPreloadData", "params": { "LeadId": "56224" } }
```

Ответ: `{ LeadId, ReglId, ClientId, IsFakeClient }`.

### Изменение — `Лид.Записать` ✅

Принимает частичную запись: обязателен `@Документ`, остальные поля —
только изменяемые.

```json
{
  "method": "Лид.Записать",
  "params": {
    "Запись": { "_type": "record", "f": 0,
      "d": [56224, "новый комментарий"],
      "s": [{ "n": "@Документ", "t": "Число целое" },
            { "n": "Примечание", "t": "Строка" }] }
  }
}
```

Ответ: `{ "result": 56224 }`. После записи обязательно перечитай карточку.

> `Лид.Записать` **не меняет этап**. `Лид.Фаза` и `Лид.Переход` принимаются
> без ошибки, но сервер оставляет прежнюю фазу.

### Удаление — `Документ.УдалитьДокументы` ✅

```json
{ "method": "Документ.УдалитьДокументы", "params": { "ИдО": [56224] } }
```

Ответ:

```json
{ "result": { "_type": "record", "f": 0,
  "d": [[56224], []],
  "s": [
    { "n": "УдаленыВКорзину", "t": { "n": "Массив", "t": "Число целое" } },
    { "n": "УдаленыНасовсем", "t": { "n": "Массив", "t": "Число целое" } }
  ] } }
```

После вызова `Удален = true`.

### Восстановление — `Документ.Восстановить` ✅

```json
{ "method": "Документ.Восстановить", "params": { "ключДокумента": 56224 } }
```

Ответ: `{ "result": "" }`. Перед восстановлением клиент проверяет номер:

```json
{ "method": "Документ.ПроверитьНаличиеНомераПоИдО", "params": { "ИдО": 56224 } }
```

`false` — номер есть, `true` — номера нет (нужно `Документ.СоздатьНомерПоИдО`).

## Состав сделки

### Товары

Состав читается через сервис счёта:

```json
{
  "method": "СчетСкИсх.DocNomListForUser",
  "params": {
    "Фильтр": { "_type": "record", "f": 0,
      "d": [true, true, true, true, true, true, true, true, true,
            "WHDNomList/grid:config-v1-columns-WHDLead_OutBill-NomList",
            true, true, true, <ИдСделки>, 0],
      "s": [
        { "n": "add_discounts_dn_info", "t": "Логическое" },
        { "n": "add_lids_bill_in_nom_rec", "t": "Логическое" },
        { "n": "add_lids_bill_in_totals_rec", "t": "Логическое" },
        { "n": "calc_access_editing_price", "t": "Логическое" },
        { "n": "calc_characteristic_params", "t": "Логическое" },
        { "n": "calc_item_type", "t": "Логическое" },
        { "n": "calc_modifiers", "t": "Логическое" },
        { "n": "calc_rp_add_fields_simple", "t": "Логическое" },
        { "n": "calc_shipped_full", "t": "Логическое" },
        { "n": "column_config_id", "t": "Строка" },
        { "n": "delete_lids_empty_bill", "t": "Логическое" },
        { "n": "init_selected_nom_set_data", "t": "Логическое" },
        { "n": "set_default_prices_for_present", "t": "Логическое" },
        { "n": "ЛидИд", "t": "Число целое" },
        { "n": "СкладскойДокумент", "t": "Число целое" }
      ] },
    "Сортировка": null,
    "Навигация": { "...": "..." },
    "ДопПоля": []
  }
}
```

Ключ — `Фильтр.ЛидИд`. Состав хранится в связанном счёте (`СчетИсх`),
флаги `add_lids_bill_in_nom_rec` / `delete_lids_empty_bill` управляют
подмешиванием и очисткой пустого счёта.

`NomCatalogBasket.getBasket` ⚠️ требует `basketype`; точная арность не
подтверждена:

```
При вызове метода "NomCatalogBasket.getBasket" не передан аргумент "basketype"!
```

### Связанные документы

Чтение:

```json
{
  "method": "Документ.СвязанныеДокументы",
  "params": {
    "ИдО": "56224",
    "Фильтр": {
      "ИмяОбъекта": "Лид",
      "ИдРегламента": "<UUID темы>"
    }
  }
}
```

Ответ — `recordset` с `@Документ`, `ИдентификаторДокумента`, `Сотрудник`,
`Подразделение`, `ДокументНашаОрганизация`, `Лицо1..3`, `Номер`, `Дата`.

Создание связанного документа — `Dokument.CreateLinkedDocument` ✅ (вызов
из меню «Создать → Счет» создал `СчетИсх`). Тело перегружено по числу полей:
снимай его с UI-запроса, а не собирай вручную.

Буфер обмена для связывания:

```json
{ "method": "SBISBuffer.GetAllObjectsInfo",
  "params": { "Filters": { "d": [false],
    "s": [{ "n": "no_cut", "t": "Логическое" }] } } }
```

## Жизненный цикл

### Смена этапа ✅ (чтение) / ⚠️ (запись)

Порядок:

1. `CRMEvent.AvailableDocCommands` — список доступных переходов из текущей фазы.
2. `CRMEvent.CreateMaster` — мастер события перехода:

```json
{
  "method": "CRMEvent.CreateMaster",
  "params": {
    "Фильтр": { "_type": "record", "f": 0,
      "d": [null, <ИдТемы>, null, 9, 0, <ИдКлиента>, <ИдСделки>, <PassId>,
            null, null, null, null, null, null, null, null, null,
            false, null, <ИдОтветственного>, false, null, null, null],
      "s": [
        { "n": "Тип", "t": "Число целое" },
        { "n": "Регламент", "t": "Число целое" },
        { "n": "RegulationsList", "t": { "n": "Массив", "t": "Число целое" } },
        { "n": "ТипКонтакта", "t": "Число целое" },

        { "n": "Документ", "t": "Число целое" },
```

Ответ `{ "result": null }`.

4. `Лид.Записать` — сохранение карточки.

Проверка результата — только перечитыванием карточки:

```js
const deal = await readDeal(id);
if (deal["Лид.Фаза"] !== expectedPhaseId) throw new Error("этап не изменился");
```

### Откат

Отдельного rollback-метода нет. Откат — такой же переход, но с обратным
`PassId` из `CRMEvent.AvailableDocCommands`. Если тема не разрешает обратный
переход, в списке его не будет.

### Смена ответственного ⚠️

Клиентский модуль использует `CRMLead.FixPlan` для одиночной сделки и
`CRMLead.FixPlanMass` для массовой. Массовый вариант:

```json
{
  "method": "CRMLead.FixPlanMass",
  "params": {
    "ActionParams": { "params": {
      "leads": [56224], "face": 3722874, "dat_plan": null,
      "comment": "комментарий", "action": "fixation" } },
    "Operation": {
      "Scenario": "DealFixationAndPlan", "TaskName": "Fixaiton",
      "RegClass": "Лид", "Type": "ByOne",
      "ReturnField": "@Документ", "Channel": "crm.deals.updated" } }
}
```

`CRMLead.FixPlan` на стенде вернул «метод не найден». Контракт не подтверждён
прямым вызовом — снимай с UI.

### Согласование ❓

`Согласование.Создать` существует, но требует запись с полем `Расширение`:

```
В объекте нет поля Расширение
```

`Документ.СоздатьСогласование`, `Документ.НаправитьНаСогласование`,
`Документ.Согласовать`, `Docflow.CreateApproval`, `Docflow.StartApproval`
на стенде не зарегистрированы. Контракт не выдумывай.

## Правила работы с данными

- Не трогай чужие сделки: создавай свою и работай только с ней.
- Комментарий делай уникальным: `АТ <цель> <дата>-<время>`.
- После каждой записи перечитывай карточку и проверяй инвариант.
- Удаление — только `Документ.УдалитьДокументы`; восстановление — `Документ.Восстановить`.
- Помни о побочных эффектах: связанные счета, события, изменения полей.
- Тестовые сущности удаляй в teardown, если сценарий это допускает.
- Секреты и учётные данные — только из `.env`.

## Чек-лист

- [ ] В запросе есть `x-adaptive: false` и корректный `x-originalmethodname`.
- [ ] `record` собран по схеме `s`/`d`, а не объектом.
- [ ] После записи карточка перечитана и проверена.
- [ ] Этап меняется событием перехода, а не `Лид.Записать`.
- [ ] Контракт, снятый с UI, помечен как проверенный; догадки — как открытый вопрос.
- [ ] Тестовая сделка уникальна, побочные эффекты зафиксированы.
