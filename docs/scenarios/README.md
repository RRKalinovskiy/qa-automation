# Сценарии

Каталог тест-сценариев проекта. Здесь фиксируем **что** проверяем, до того как писать код.

## Формат

- Один файл — одна функциональная область: `docs/scenarios/<area>.md`.
- Один сценарий — один блок по шаблону [`_template.md`](./_template.md).
- ID: `TC-<AREA>-<NNN>`, где `AREA` — короткий код области (`AUTH`, `CART`, `ORDER`), `NNN` — номер с ведущими нулями.
- Примеры: `TC-AUTH-001`, `TC-CART-014`.

## Карты функционала

Снимки структуры существующих проверок Saby — не заменяют сценарии,
но помогают понять покрытие и выбрать, что описывать и автоматизировать.

- [Проверка № 2607: карточка ФЛ](./client-card-2607-function-map.md) —
  карта функционала, статусы, пробелы и кандидаты в сценарии.
- [Проверка № 2607: поточечный перечень](./client-card-2607-points.md) —
  все 73 пункта с разделами, статусами и `docId`.

## Статусы

| Статус | Значение |
|---|---|
| `draft` | Черновик, требования не подтверждены. |
| `ready` | Согласован, готов к автоматизации. |
| `automated` | Покрыт автотестом, тест зелёный. |
| `manual` | Остаётся ручным (указать причину). |
| `skipped` | Не проверяем (указать причину и ссылку на решение). |

## Приоритеты

| Приоритет | Значение |
|---|---|
| `P0` | Критичный путь: без него продукт не работает. |
| `P1` | Основной функционал и типовые ошибки. |
| `P2` | Редкие сценарии, граничные значения, косметика. |

## Процесс

1. Собери требования, контракт API, макеты и доступы к стенду.
2. Построй карту функционала: экраны, эндпоинты, состояния, роли.
3. Разложи проверки по классам: позитивные, негативные, граничные, права доступа, восстановление после ошибок.
4. Оформи сценарии по шаблону, включая данные и постусловия.
5. Согласуй открытые вопросы с владельцем требований.
6. Отметь кандидатов на автоматизацию: API — в первую очередь, UI — пользовательские пути.
7. После автоматизации обнови статус и матрицу трассировки.

## Definition of Ready

- [ ] Понятны предпосылки и роль пользователя.
- [ ] Шаги однозначны, ожидаемый результат проверяем.
- [ ] Определены тестовые данные и способ очистки.
- [ ] Известны ограничения окружения.
- [ ] Нет открытых вопросов, блокирующих автоматизацию.
