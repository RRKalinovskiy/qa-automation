# Проект: UI- и API-автотесты

## Назначение

Учебно-рабочий проект полного цикла QA:

1. Изучаем требования и функционал.
2. Проектируем тест-сценарии.
3. Создаём тестовые данные.
4. Пишем API- и UI-автотесты.
5. Поддерживаем трассировку «требование → сценарий → автотест».

## Стек

- **Playwright Test + TypeScript** — UI- и API-автотесты.
- **Postman / Newman** — контракты, коллекции, моки, мониторинг (по необходимости).
- **Zod** — валидация схем ответов API.
- **Node.js 20+**.

## Рабочий процесс

1. **Контекст.** Собери требования, OpenAPI/коллекцию Postman, доступы к стенду. Не додумывай поведение — фиксируй вопросы.
2. **Сценарии.** Заведи `docs/scenarios/<area>.md` по шаблону `docs/scenarios/_template.md`. ID: `TC-<AREA>-<NNN>`.
3. **Данные.** Опиши набор в `docs/test-data/<area>.md` по шаблону, добавь фабрику в `src/data/factories/`.
4. **API-тесты.** Сначала покрывай API: быстрее, стабильнее, готовит данные для UI. Файлы — `tests/api/<area>.spec.ts`.
5. **UI-тесты.** Только пользовательские пути через Page Object. Файлы — `tests/ui/<area>.spec.ts`.
6. **Трассировка.** Обнови матрицу в `docs/scenarios/README.md`: сценарий → автотест → статус.

## Правила

### Общие

- Документация — на русском, код и идентификаторы — на английском.
- Один сценарий проверяет одну цель; негативные и граничные кейсы — отдельно.
- Тесты независимы: порядок запуска и параллельность не должны влиять на результат.
- Секреты только в `.env` (файл в `.gitignore`), в репозиторий — `.env.example`.
- Не использовать реальные персональные данные. Только зарезервированные значения: `example.com`, телефоны `+1 555 …`.

### API

- Проверять статус, `Content-Type`, схему ответа и бизнес-инварианты.
- Данные создавать через API и удалять в teardown; не полагаться на общий стенд.
- Авторизация — через `API_TOKEN` и `src/api/client.ts`.
- Контрактные тесты синхронизировать с OpenAPI/коллекцией Postman.

### UI

- Только Page Object Model (`src/ui/pages/`), локаторы — внутри страниц.
- Приоритет локаторов: `getByRole` → `getByLabel` → `getByTestId` → CSS.
- Запрещены XPath, `waitForTimeout` и «магические» паузы.
- Ожидания — web-first assertions (`expect(locator).toBeVisible()`).
- Каждый тест сам готовит своё состояние; авторизация — через `storageState`.

## Команды

```bash
npm install                  # зависимости
npx playwright install chromium
npm run test:api             # API-проект
npm run test:ui              # UI-проект
npm run test:smoke           # тесты с @smoke
npm run test                 # всё
npm run test:mcp             # unit + smoke MCP saby-checks
npm run test:mcp:e2e         # MCP поверх локального мока Saby
npm run typecheck            # проверка типов
npm run report               # HTML-отчёт
npm run saby:login           # сохранить сессию Saby в .auth/saby.json
npm run saby:session         # проверить авторизацию Saby
npm run mcp:saby             # запустить MCP вручную (stdio)
```

## MCP проверок Saby

- Сервер: `mcp/saby-checks/server.mjs`, инструменты `saby_check_*`.
- Конфигурация: `opencode.jsonc` → `mcp.saby-checks`.
- Авторизация: `npm run saby:login` (storageState) или `SABY_COOKIE`.
- Контракты: `docs/api/sbis-checks.md`.
- Навыки: `saby-checks` (написание проверки), `saby-checks-api` (контракты и поддержка).

## Правила оформления тестов Saby

1. Название теста начинается с `ТК` (тест-кейс), `ЧЛ` (чек-лист) или `Т` (требование).
2. Короткое описание, что проверяем, — в «Общее описание» → «Комментарий».
3. Предварительные шаги — в «Общее описание» → «Описание».
4. В предварительных шагах — основные шаги подготовки к тесту.
5. Предусловие — в формате:
   ```text
   ПРЕДУСЛОВИЕ:
   1. ...
   ```
6. Плановое время — не более 5 минут на сценарий.
7. Пометки: флаг — ПК; красный — важный МК; жёлтый — незначительный МК;
   зелёный — МК не критичный функционал; синий — АТ.
8. Описание того, что делаем, не должно совпадать с названием кейса.

Данные сценария не пишутся в поле статуса («Текущее состояние»).
Для этого есть отдельные поля «Комментарий» и «Описание».

Правила проверяются MCP `saby-checks` (инструмент `saby_check_rules`) и
навыком `saby-checks`.

## Definition of Done

- [ ] Сценарии оформлены и имеют ID.
- [ ] Для сценария определены данные и способ очистки.
- [ ] Автотест проходит локально и в параллельном запуске.
- [ ] Нет `waitForTimeout`, XPath и общих изменяемых данных.
- [ ] Обновлена матрица трассировки.
- [ ] `npm run typecheck` и релевантный набор тестов зелёные.
